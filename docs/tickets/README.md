# 티켓 문서 운영 규칙

`docs/tickets/`는 이슈별 원인 분석과 대응 계획을 보관한다. 각 파일은 사용자가 티켓을 열었거나
명시적으로 문서화한 시점의 **계획 스냅샷**이다. 진행 로그나 현재 상태 문서가 아니다. 현재 지식은
[위키](../wiki/README.md)에, 티켓 계획이 다듬어진 과정은 [리뷰 기록](../ticket-reviews/README.md)에 둔다.

## 목적과 범위

- 티켓 또는 하위 작업 하나당 마크다운 파일 하나를 둔다.
- 문서에는 개요, 문제 정의, 결정 사항, 테스트 계획, 구현 계획, 범위, 비목표, 참고만 담는다.
- 이후 방향이 바뀌어도 과거 티켓을 소급 수정하지 않는다. 후속 작업은 새 티켓으로 남긴다.
- 티켓 ID는 사람이 부여한다. ID 없이 티켓 작성을 요청받으면 먼저 ID를 확인한다.

## 에이전트 제약

- 사용자가 명시적으로 요청하지 않는 한 `docs/tickets/` 아래에 파일을 만들거나 수정하지 않는다.
- 구현 진행, 상태 메모, 결과, 회고, 실행 로그를 티켓에 덧붙이지 않는다.
- 표현 정리, 오타 수정, 링크 수정 같은 자발적 개선도 하지 않는다. 발견한 문제는 사용자에게 알린다.
- 티켓과 리뷰 기록은 각각 확정 시점에 한 번 작성한 뒤 수정하지 않는다.

## 관례

- 본문은 한국어로 쓴다.
- 파일명은 `{ISSUE-ID}-{sub-number}-{English-Title-Slug}.md`다. 예:
  `ISSUE-001-01-Homepage.md`.
- 브랜치는 `feature/ISSUE-{NNN}.{NN}-{PascalCaseTitle}` 형식을 쓴다.
- 구현 계획은 테스트 계획을 먼저 정의하는 TDD 구조를 따른다.
- 티켓은 위키나 코드를 참조할 수 있지만, 위키는 고정된 티켓 문서에 의존하지 않는다.

## 템플릿

```markdown
# {티켓 제목}

## 개요

### 목표

### 배경

### 영향 범위

### 비목표

### 참고

## 문제 정의

### 증상

### 근본 원인

### 제약

## 결정 사항

## 테스트 계획

### 테스트 케이스

### 구현 전 예상 실패

### 검증 기준

## 구현 계획

### 순서

### 리스크와 롤백
```
