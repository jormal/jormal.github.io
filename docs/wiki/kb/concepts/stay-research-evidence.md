# 숙소 조사 원문 요약과 후기 균형

숙소 조사는 원문 내용을 먼저 요약해 저장하고, 그 요약에서 분석에 채택한 경험을
명시한다. URL 수, 전체 평점에 포함된 후기 수, 실제 채택 경험 수는 서로 다르다.

사용자가 정한 조건은 **도시별·전체 한국 후기 ≥ 전체 외국 후기**다.
Reddit만 제한하는 규칙이 아니며 외국 포럼·블로그·번역 원문에도 동일하게 적용한다.
한국어로 표시되는 예약 사이트라도 번역 후기나 집계 평점을 한국인 원문으로 세지 않는다.
동일 작성자의 같은 숙소 경험·추가 답글은 하나로 세고, 짧은 질문·숙소명 제안·제휴 목록은
실제 투숙 후기 수에 넣지 않는다. 부정 경험도 판단 근거로 함께 보존한다.

`temp/iberian-stay-source-summaries.json`은 원문 URL·요약·작성일·열람 한계 및
`analysis.reviews`의 개별 채택 경험, `analysis.comparisons`의 판단 연결을 담는다.
열람 실패 자료는 내용을 추정하지 않고 실패 사유와 URL을 보존한다.
본문을 읽었다는 상태는 추천 채택·최근 투숙·독자 반응 검증을 의미하지 않는다.

통합 열람 문서는 `temp/iberian-stay-social-research.html`이다.
기존 조사표는 현재 분석과 구분된 보관 영역에 남아 있으며 기존 점수를 재사용하지 않는다.
원문·경험을 갱신한 뒤 다음 명령으로 HTML을 맞추고 검증한다.

```sh
python3 scripts/render-stay-research.py
python3 scripts/render-stay-research.py --check
node scripts/verify-static-site.mjs
```

후기 균형 검사는 도시별 경험·원문 수, 중복 식별자·경험, 미열람 근거의 채택,
비교표의 누락된 인용 및 JSON과 HTML의 불일치를 검사한다.
작성자 진위·경험의 독립성·내용 정확성은 자동 검사만으로 보장되지 않으므로 원문 검토가 필요하다.
화면 변경은 로컬 서버와 브라우저에서도 확인한다.

## 이동 동선에 따른 권역 순위

숙소 우선순위는 보호된 일정의 실제 출발·도착 거점으로 계산한다. 캐리어를 든 날은
택시가 진입·승하차할 수 있는지, 짐 보관·회수와 차량 기본 주행 시간을 기준으로 한다.
관광 중에는 짐 없이 대중교통·도보 접근성을 따로 판단한다. 두 기준을 섞어 “가깝다”라고
표현하지 않는다.

`analysis.city_context.movement_glossary`에는 한국어 명칭(현지 표기)과 지점 역할을,
`analysis.city_context.movement_points`에는 도시별 실제 승하차 지점, 캐리어를 든 이동,
확인 상태를 먼저 둔다. 버스 터미널과 철도역이 연결되어도 승강장이 같다고 쓰지 않으며,
열차의 중간 정차역과 종착역도 구분한다. 샌딩 투어처럼 집결·종료 지점이 확인되지 않은
구간은 권역 경로 계산에 넣지 않고 `판매자 확인 불가`로 표시한다.

`analysis.city_context.area_notes`에는 권역별 `rank`, `route`, `pros`, `cons`를 둔다.
`route`는 일정 거점과 권역 대표점 사이의 공개 도로 경로 기본 주행 시간이며, 교통량·택시
호출 대기·숙소 안팎 이동은 포함하지 않는다. 이 한계를 표에 그대로 표시하고, 경로 결과와
관광성·숙소 후기의 캐리어 마찰점을 함께 반영해 순위를 정한다. 개별 숙소 주소를 외부 서비스에
일괄 전송해 경로를 계산하지 않는다.

현재 비교표의 각 숙소에는 `analysis.hotel_areas`로 단일 권역을 지정한다. 복수 권역을
합친 과거 수집 묶음은 근거 연결에만 남기고, 화면의 권역 행·숙소 행에는 사용하지 않는다.
게스트하우스는 원문 장부에 보존할 수 있으나 현재 허니문 비교에는 호텔·아파트호텔·2인 전용
아파트를 우선하며, 대체 후보가 있으면 제외한다.

권역 순위와 숙소 순위도 분리한다. 실제 이동 경로가 우세한 권역은 개별 숙소의 계단·객실 크기
같은 결점 때문에 권역 순위를 낮추지 않는다. 그 결점은 해당 숙소의 장단점과 최종 선택에서만
반영한다.

일정 조건은 [비공개 여행 일정의 단계적 구체화](private-itinerary-planning.md)에 따라
현재 보호된 일정을 읽어 확인한다. 이전 조사표의 숙소가 현재 숙소와 같다고 가정하지 않는다.
복호화 구문과 상세 일정 평문을 위키에 기록하지 않는다.

## 자료 파일의 역할과 문서 구조

현재 자료는 `temp/iberian-stay-source-summaries.json` 하나에만 갱신한다.
`_meta`에 목적·스키마 버전·필드 형식·수정 규칙·소비자를 기록했다.
원문은 `sources`, 채택 경험은 `analysis.reviews`, 일정 비교는
`analysis.comparisons`, 호텔별 타입·장점·단점은 `analysis.comparison_details`,
도시별 일정 조건·권역 우선 이유는 `analysis.city_context`, 도시별 권역·숙소 행과
원문 목록은 `catalog`에 둔다. 각 JSON 필드는 `_meta.format`에도 목적과 형식을 적는다.
재수집은 기존 원문 ID의 `retrieval_attempts`에 누적하고 별도 retry/additions JSON을 만들지 않는다.

과거 분할 수집 JSON 10개는 `temp/iberian-stay-research-archive.json`의
`legacy_documents`에 원래 파일명·내용을 보존해 통합했다. 이 파일의 목적은 과거 기록
보존이며 현재 판단·집계에는 사용하지 않는다. 당시 HTML과 구조화한 이전 카탈로그도
이 보관 파일에 남긴다. 각 파일의 `_meta.format`이 상세 형식의 기준이다.
렌더러는 이 두 파일 외에 `iberian-stay-*.json`이 생기면 검증에 실패한다.

HTML은 JSON에서 생성하며 브라우저의 외부 서비스나 런타임 fetch에 의존하지 않는다.
집계 요약 → 도시별 일정 조건·권역 우선 이유 → 숙소별 1행 비교(숙소명·타입·권역·장점·단점·레퍼런스) → 권역·숙소를 같은 행에 둔 전체 후보 카탈로그 →
채택 후기 → 전체 원문 장부 → 접힌 이전 조사 순서다. 위치 근거가 없는 후보는
미분류로 보존하고, 권역명이 숙소 수에 들어가지 않도록 한다.
수집 URL·본문 확인 자료·개별 채택 경험·현재 비교 숙소·전체 카탈로그 숙소는
서로 다른 집계다. 같은 원문이 여러 도시를 다루면 도시별 원문 합과 전체 고유 원문 수가 다르다.

## 열람 실패 재시도

공개 웹 도구의 실패가 원문 삭제나 잘못된 링크를 뜻하지는 않는다. 일반 Chrome 렌더링과
Reddit의 동일 게시글 ID를 유지한 주소 변형을 시도해 본문을 확인할 수 있었다.
기존 주소와 작동한 주소·방법·결과를 남긴다. 인증·CAPTCHA는 우회하지 않는다.
재시도 후에도 실패한 원문은 링크 무효로 단정하거나 내용을 추정하지 않는다.

Booking 후기 주소가 숙소 소개 페이지로 이동하면 선택 후기 발췌를 읽을 수 있어도
전체 후기·게시일 검증과 구분한다. 날짜 없는 발췌를 최근 채택 후기 수에 더하지 않는다.
객실 내 캐리어 공간·침대 수납함·로비 대기와 체크아웃 후 짐 보관은 서로 다른 근거다.

허니문 숙소 비교에는 두 사람이 단독으로 묵는 객실·아파트·개인실만 둔다. 도미토리형
숙소의 원문은 수집 장부에 남길 수 있지만 현재 숙소 비교·후기 집계·후보 카탈로그에는
넣지 않는다. 개인실이 명시된 호스텔은 실제 예약 시 2인 전용 여부를 다시 확인한다.
