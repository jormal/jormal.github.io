# 비공개 여행 일정의 단계적 구체화

## 목적

정적 웹사이트에서 여행의 분위기와 큰 흐름은 보여 주되, 실제 날짜·항공편·숙소·예약 정보는 함께
열람하는 사람만 볼 수 있게 한다. 일정은 한 번에 확정하지 않고, 두 사람의 취향과 피로도 기준을
질문으로 수집하며 점진적으로 구체화한다.

## 공개와 비공개의 경계

공개 페이지에는 여행의 제목, 대략적 기간, 도시 순서, 확정 전 후보와 같은 낮은 민감도의 정보만 둔다.
공개 초안에서 일자 번호별 도시 흐름, 대략적인 이동 시간, 항공권을 제외한 넓은 예산 범위를 보여 주는 것은
허용한다. 이 정보는 계획을 함께 검토하기 위한 범위이며 실제 예약값이나 실시간 위치가 아니다.
다음 정보는 평문으로 저장소, 위키, 이슈, HTML, JavaScript, URL에 넣지 않는다.

- 정확한 출발·도착 시각과 항공편 번호
- 숙소명, 예약 번호, 연락처, 실시간 위치
- 정확한 일자별 동선, 실제 비용 합계와 결제 내역
- 비밀 구문과 복호화 키

상세 일정은 암호문만 정적 파일로 두고, 열람자가 브라우저에서 입력한 비밀 구문으로 복호화한다.
비밀 구문은 별도 안전 채널로 공유하며 저장소, URL, `localStorage`에 남기지 않는다. 이 방식은 내용을
숨기지만, 키를 전달받은 사람이 내용을 복사하는 것까지 막거나 권한 철회·열람 감사를 제공하지는 않는다.

## 초안에서 확정까지

1. **동선 골격:** 입·출국 도시, 필수 체류일, 장거리 이동 횟수의 상한을 정한다.
2. **취향 인터뷰:** 숙소의 성격, 하루의 보행량, 음식·예술·자연·휴식의 우선순위, 예산의 유연성을
   짧은 질문으로 수집한다.
3. **후보 비교:** 중간 도시마다 이동 시간, 숙박 최소일, 두 사람의 우선순위, 계절성을 한 표에서 비교한다.
4. **일자별 편성:** 하루에 앵커 하나와 여백 하나를 두고, 이동일에는 새 도시의 첫 산책 외 일정을 과도하게
   넣지 않는다.
5. **비용 봉투:** 항공권을 제외한 숙소·도시간 이동·식사·경험·예비비로 분리해 상한과 목표를 결정한다.
6. **비공개 발행:** 확정 내용은 로컬의 비추적 원본에서 암호문으로 변환하고, 공개 페이지에는 암호문과
   복호화 UI만 반영한다.

## 다음 인터뷰에서 확인할 질문

- 숙소는 디자인·분위기, 넓이·욕조·휴식, 위치·동선 중 무엇이 가장 중요한가?
- 하루 종일 걷는 날은 며칠까지 편안한가? 낮잠·카페·숙소 휴식은 얼마나 필요한가?
- 음식, 와인, 건축·미술, 자연·바다, 사진, 쇼핑 중 꼭 남기고 싶은 두 가지는 무엇인가?
- 중간 도시를 하나 더 들르는 대신 이동을 늘리는 선택을 어느 정도까지 받아들일 수 있는가?
- 항공권 제외 2인 총예산의 목표·상한은 무엇이며, 숙소와 경험 중 어디에 더 쓰고 싶은가?

## 구현 상태

`info/`는 여정의 요약과 개별 계획으로 가는 길을 제공한다. 계획별 공개 페이지는 도시별 일자 흐름,
대략적 이동, 넓은 예산 범위와 결정할 질문을 보이고, `data.enc.json` 암호문은 비밀 구문으로만 복호화한다.
`scripts/encrypt-itinerary.mjs`는 `private/`
아래의 비추적 원본을 암호문으로 변환하며, 비밀 구문은 대화·저장소·브라우저 저장소에 남기지 않는다.
