# 비공개 여행 일정의 단계적 구체화

## 목적

정적 웹사이트에서 여행의 분위기와 큰 흐름은 보여 주되, 실제 날짜·항공편·숙소·예약 정보는 함께
열람하는 사람만 볼 수 있게 한다. 일정은 한 번에 확정하지 않고, 두 사람의 취향과 피로도 기준을
질문으로 수집하며 점진적으로 구체화한다.

## 공개와 비공개의 경계

공개 페이지에는 여행의 제목, 대략적 기간, 도시 순서와 도시별 숙박 수만 둔다.
예산 범위, 경로 선택지, 정확한 이동 시간은 공개하지 않는다.
다음 정보는 평문으로 저장소, 위키, 이슈, HTML, JavaScript, URL에 넣지 않는다.

- 정확한 출발·도착 시각과 항공편 번호
- 숙소명, 예약 번호, 연락처, 실시간 위치
- 정확한 일자별 동선, 실제 비용 합계와 결제 내역
- 비밀 구문과 복호화 키

상세 일정은 암호문만 정적 파일로 두고, 열람자가 브라우저에서 입력한 비밀 구문으로 복호화한다.
비밀 구문은 별도 안전 채널로 공유하며 저장소, URL, `localStorage`에 남기지 않는다. 이 방식은 내용을
숨기지만, 키를 전달받은 사람이 내용을 복사하는 것까지 막거나 권한 철회·열람 감사를 제공하지는 않는다.

## 초안에서 확정까지

1. **동선 골격:** 입·출국 도시, 필수 체류일, 장거리 이동 횟수의 상한을 정한다.
2. **취향 인터뷰:** 숙소의 성격, 하루의 보행량, 음식·예술·자연·휴식의 우선순위, 예산의 유연성을
   짧은 질문으로 수집한다.
3. **후보 비교:** 중간 도시마다 이동 시간, 숙박 최소일, 두 사람의 우선순위, 계절성을 한 표에서 비교한다.
4. **일자별 편성:** 하루에 앵커 하나와 여백 하나를 두고, 이동일에는 새 도시의 첫 산책 외 일정을 과도하게
   넣지 않는다.
5. **비용 봉투:** 항공권을 제외한 숙소·도시간 이동·식사·경험·예비비로 분리해 상한과 목표를 결정한다.
6. **비공개 발행:** 확정 내용은 로컬의 비추적 원본에서 암호문으로 변환하고, 공개 페이지에는 암호문과
   복호화 UI만 반영한다.

## 현재 확인 방식

확정한 일정은 제공자 원문에서 시간·장소·주소를 직접 확인하고, 확인일과 URL을 보호된 원본에
함께 기록한다. 페이지를 읽지 못한 값은 추정하지 않고 `페이지 확인 불가`로 둔다.
매 투어 종료와 교통편 도착 뒤에는 숙소↔출발·도착·집결지 이동 수단·소요 시간과 그 산정 기준을 함께 기록한다.

## 구현 상태

`info/`는 여정의 낮은 민감도 개요와 개별 계획으로 가는 길을 제공한다. 계획별 공개 페이지는 도시 순서와
숙박 수만 보이고, `data.enc.json` 암호문은 비밀 구문으로만 복호화한다.
`scripts/encrypt-itinerary.mjs`는 `private/`
아래의 비추적 원본을 암호문으로 변환하며, 비밀 구문은 대화·저장소·브라우저 저장소에 남기지 않는다.

## 숙소 조사와 동선 판단 원칙

- 후기 근거는 도시별·전체에서 한국인 원문 후기가 외국 후기 이상이 되게 하며, 번역 후기·집계 평점은 세지 않는다.
- 같은 작성자의 같은 숙소 경험은 하나로 세고, 짧은 질문·숙소명 제안·제휴 목록은 제외한다. 부정 경험도 보존하며, 날짜 없는 발췌는 최근 후기로 취급하지 않는다.
- 원문을 열지 못했더라도 링크 무효나 내용을 단정하지 않고, 인증·CAPTCHA는 우회하지 않으며 시도 방법과 결과를 남긴다.
- 비교 대상은 두 사람이 단독으로 쓰는 객실·아파트·개인실로 한정하고 도미토리형은 제외한다.
- 캐리어 이동(택시 진입·승하차, 짐 보관·회수, 차량 주행)과 관광 중 이동(대중교통·도보)을 분리한다. 도로 경로의 기본 주행 시간에는 교통량·호출 대기·숙소 안팎 이동이 포함되지 않음을 함께 적는다.
- 개별 숙소 주소를 외부 서비스에 일괄 전송해 경로를 계산하지 않으며, 권역 순위와 개별 숙소 순위도 분리한다.
